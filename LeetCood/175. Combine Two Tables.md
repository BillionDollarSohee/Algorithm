[리트코드 175. 두 테이블 합치기](https://leetcode.com/problems/combine-two-tables/)

난이도: Easy

테이블: `Person`

```
+-------------+---------+
| 컬럼명       | 타입     |
+-------------+---------+
| personId    | int     |
| lastName    | varchar |
| firstName   | varchar |
+-------------+---------+
personId는 이 테이블의 기본키(PRIMARY KEY)이다.
이 테이블은 사람들의 ID와 이름(성, 이름) 정보를 담고 있다.
```

테이블: `Address`

```
+-------------+---------+
| 컬럼명       | 타입     |
+-------------+---------+
| addressId   | int     |
| personId    | int     |
| city        | varchar |
| state       | varchar |
+-------------+---------+
addressId는 이 테이블의 기본키(PRIMARY KEY)이다.
이 테이블의 각 행은 personId에 해당하는 사람의 도시(city)와 주(state) 정보를 담고 있다.
```

문제 : Person 테이블에 있는 각 사람의 성(lastName), 이름(firstName), 도시(city), 주(state)를 조회하는 쿼리를 작성하라. 만약 해당 personId의 주소 정보가 Address 테이블에 없다면 city와 state는 null로 표시한다. 결과 테이블의 순서는 상관없다.

입력 :

```
Person table:
+----------+----------+-----------+
| personId | lastName | firstName |
+----------+----------+-----------+
| 1        | Wang     | Allen     |
| 2        | Alice    | Bob       |
+----------+----------+-----------+

Address table:
+-----------+----------+---------------+------------+
| addressId | personId | city          | state      |
+-----------+----------+---------------+------------+
| 1         | 2        | New York City | New York   |
| 2         | 3        | Leetcode      | California |
+-----------+----------+---------------+------------+
```

출력 :

```
+-----------+----------+---------------+----------+
| firstName | lastName | city          | state    |
+-----------+----------+---------------+----------+
| Allen     | Wang     | Null          | Null     |
| Bob       | Alice    | New York City | New York |
+-----------+----------+---------------+----------+
```

설명 : personId = 1인 사람은 Address 테이블에 주소 정보가 없으므로 city, state가 null로 반환된다. addressId = 1은 personId = 2인 사람의 주소 정보를 담고 있다.

---

## 풀이 개념 설명

핵심은 "매칭 안 되는 행을 버릴 것이냐, 남길 것이냐"이다.

INNER JOIN을 쓰면 Person과 Address 양쪽에 personId가 모두 존재하는 행만 남는다. personId = 1은 Address에 없으므로 결과에서 통째로 사라진다. 하지만 문제는 "주소가 없으면 null로 표시하라"고 했지 "빼라"고 하지 않았다.

LEFT JOIN을 쓰면 왼쪽 테이블(Person)을 기준으로 전부 살리고, 오른쪽 테이블(Address)에 매칭되는 행이 없으면 그 자리를 null로 채운다. 이게 문제가 요구하는 출력과 정확히 일치한다.

판단 기준 : "기준이 되는 쪽 데이터는 무조건 다 나와야 하고, 없는 정보는 null로 채워야 한다"는 조건이 보이면 LEFT JOIN(또는 반대 방향의 RIGHT JOIN)을 써야 한다는 신호다. 반대로 "양쪽 다 있는 것만"이라고 하면 INNER JOIN이다.

## SQL 풀이

```sql
SELECT
    p.firstName,
    p.lastName,
    a.city,
    a.state
FROM Person p
LEFT JOIN Address a
    ON p.personId = a.personId;
```
