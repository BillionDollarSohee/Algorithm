[리트코드 181. 매니저보다 급여가 높은 직원](https://leetcode.com/problems/employees-earning-more-than-their-managers/)

난이도: Easy

테이블: `Employee`

```
+-------------+---------+
| 컬럼명       | 타입     |
+-------------+---------+
| id          | int     |
| name        | varchar |
| salary      | int     |
| managerId   | int     |
+-------------+---------+
id는 이 테이블의 기본키(PRIMARY KEY)이다.
이 테이블의 각 행은 직원의 ID, 이름, 급여, 그리고 그 직원의 매니저 ID를 나타낸다.
```

문제 : 자신의 매니저보다 급여가 더 높은 직원을 찾는 쿼리를 작성하라. 결과 테이블의 순서는 상관없다.

입력 :

```
Employee table:
+----+-------+--------+-----------+
| id | name  | salary | managerId |
+----+-------+--------+-----------+
| 1  | Joe   | 70000  | 3         |
| 2  | Henry | 80000  | 4         |
| 3  | Sam   | 60000  | Null      |
| 4  | Max   | 90000  | Null      |
+----+-------+--------+-----------+
```

출력 :

```
+----------+
| Employee |
+----------+
| Joe      |
+----------+
```

설명 : 매니저보다 급여가 높은 직원은 Joe뿐이다.

---

## 첫 시도 (실패)

```sql
SELECT Employee
FROM Employee
WHERE salary >
(SELECT salary
FROM Employee
WHERE managerId IS NOT NULL)
```

실패 원인 두 가지.

1. `Employee`라는 컬럼 자체가 테이블에 없음. 조회해야 할 건 `name` 컬럼.
2. 서브쿼리가 "각자의 매니저"와 연결되지 않음. `managerId IS NOT NULL`인 모든 직원의 salary를 통째로 반환하기 때문에, Joe든 Henry든 상관없이 같은 서브쿼리 결과와 비교하게 됨. 실제로는 "Joe는 Joe의 매니저와, Henry는 Henry의 매니저와" 각각 따로 비교해야 하는데 그 연결고리가 없음. 서브쿼리가 여러 행을 반환하므로 `Subquery returns more than 1 row` 에러 발생.

## 풀이 개념 설명

핵심은 **self join**으로 "나"와 "내 매니저"를 한 행에 나란히 놓는 것.

- 한 테이블 안에서 어떤 행이 다른 행을 가리키는 구조(직원→매니저, 카테고리→상위카테고리 등)가 보이면 self join을 의심.
- 같은 테이블을 별명만 바꿔서 두 번 사용: 직원 관점의 별명(A)과 매니저 관점의 별명(B).
- `A.managerId = B.id` 로 "이 직원의 managerId가 = 어떤 사람의 id"인지 연결한 뒤, `A.salary > B.salary` 로 비교.

## SQL 풀이 (성공)

```sql
SELECT A.name AS Employee
FROM Employee A
JOIN Employee B
    ON A.managerId = B.id
WHERE A.salary > B.salary;
```
